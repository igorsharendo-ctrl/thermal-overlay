# ThermalOverlay

Небольшой виджет для Windows 11 x64 на C++17 и Win32. Окно всегда поверх обычных окон, поддерживает перетаскивание, прозрачность и изменение цвета. CPU и GPU отображаются одновременно в двух горизонтально расположенных карточках с обрамлением (CPU слева, GPU справа); в каждой по умолчанию есть загрузка и температура. Недоступные значения обозначаются `--`.

## Запуск и управление

Запустите `build/ThermalOverlay.exe`. Установка, .NET и отдельный Visual C++ Redistributable не нужны. Повышенные права самому виджету не требуются.

- Перетаскивание: за заголовок THERMAL, заголовки карточек или свободную область.
- Нажмите строку «Загрузка» или «Температура»: откроется список источников для этой строки. Выбор сразу применяется и сохраняется. У выбранного пункта стоит отметка.
- ПКМ или кнопка «Меню»: общие настройки, видимость показателей, прозрачность, цвет фона, автозагрузка, справка и выход.
- Кнопка «−» между меню и закрытием сворачивает окно в трей. Нажатие на значок возвращает окно; ПКМ по значку открывает «Показать» и «Выход». Повторный запуск EXE также возвращает скрытое окно.
- Кнопка закрытия справа оформлена отдельно и подсвечивается красным при наведении. Она полностью завершает программу. Окно имеет скруглённые углы.
- «Запускать при входе в Windows» добавляет или удаляет запись текущего пользователя в `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`. По умолчанию выключено. После переноса EXE в другой каталог выключите и снова включите этот пункт; системное отключение автозагрузки через Диспетчер задач может дополнительно блокировать запуск.
- Карточки CPU и GPU остаются видимыми: последний показатель в каждой карточке отключить нельзя.
- Прозрачность от 0 до 80%; цвет можно выбрать из готовых или задать самостоятельно. Прозрачность применяется ко всему окну, включая текст и рамки. На светлом фоне обрамление и текст тёмные для читаемости.
- Положение окна, цвет, прозрачность, видимость строк и выбранные источники сохраняются сразу в `%LOCALAPPDATA%\ThermalOverlay\settings.ini`.
- После отключения монитора окно перемещается в доступную рабочую область. Поддерживается масштабирование DPI на разных мониторах.

## Графики

Под показателями каждой карточки отображаются графики загрузки и температуры за последние 3 минуты. Шкалы: 0–100 % и 0–150 °C. История заполняется с момента запуска, хранится только в памяти и продолжает собираться при сворачивании в трей. Недоступные значения и длительные задержки дают разрыв линии. При смене источника очищается история только этого показателя. Видимость графика следует за видимостью соответствующей строки.

## Источники данных и ограничения

CPU, загрузка: `GetSystemTimes`, средняя загрузка всех логических процессоров основной процессорной группы. На машинах с более чем 64 логическими процессорами это ограничение Windows API нужно учитывать.

GPU, загрузка: Windows PDH `GPU Engine`. Значения процессов суммируются отдельно для каждого аппаратного движка, затем выбирается самый загруженный движок среди GPU. Это не сумма процентов всех движков. Тот же принцип используется Диспетчером задач. В меню доступны отдельные движки Windows (3D, Copy и другие, которые предоставляет драйвер). Замеры выполняются с интервалом около секунды; несовпадающие моменты обновления могут давать разные цифры при меняющейся нагрузке.

GPU, температура: `D3DKMTQueryAdapterInfo`, `KMTQAITYPE_ADAPTERPERFDATA`, максимум доступных температур аппаратных адаптеров. Значение зависит от поддержки драйвером; показания округляются до целых градусов, как в Диспетчере задач. Загрузка и максимальная температура при нескольких GPU могут относиться к разным адаптерам.

На NVIDIA дополнительно доступны температура и загрузка каждой GPU через штатную `nvml.dll` из драйвера. Они выбираются вручную в меню строки. NVML использует другую методику загрузки, поэтому его процент не обязан совпадать с Диспетчером задач. Отсутствие NVML не мешает работе.

CPU, температура: максимум доступных температур CPU из локального WMI-провайдера запущенного [Libre Hardware Monitor](https://github.com/LibreHardwareMonitor/LibreHardwareMonitor/releases). Он также добавляет в выпадающие меню отдельные датчики CPU/GPU: ядра, пакет CPU, отдельные нагрузки и температуры. Для доступа к аппаратным датчикам самому Libre Hardware Monitor могут потребоваться права администратора. Он не включён в поставку и не запускается виджетом автоматически. Идентификатор рядом с названием помогает различать одноимённые датчики разных устройств.

**У Windows нет универсального пользовательского API температуры CPU.** Без доступного провайдера эта температура будет `--`. Температура ACPI-зоны не выдаётся за температуру CPU. Если выбранный датчик отключился или исчез, виджет сохраняет выбор и показывает `--` до его возвращения. Первая загрузка может появиться через несколько секунд. Номинальный интервал опроса — одна секунда (при долгом ответе провайдера он может увеличиться); работа провайдера не блокирует интерфейс.

Поверх полноэкранных игр в эксклюзивном режиме и защищённого рабочего стола Windows отображение не гарантируется. Для игр подходит оконный режим без рамки. Сборка x64 рассчитана на Windows 11 x64; работа на Windows on ARM через эмуляцию отдельно не проверялась. Поддержку датчиков на каждом компьютере гарантировать нельзя.

## Сборка

Переносимый LLVM-MinGW (UCRT, x86_64), PowerShell:

```powershell
.\build.ps1 -Compiler 'X:\tools\llvm-mingw\bin\clang++.exe'
```

Путь в примере условный. Если `clang++` есть в PATH, достаточно `./build.ps1`. Получится `build/ThermalOverlay.exe`. Скрипт не содержит путей конкретного пользователя и не скачивает зависимости.

Также есть CMake-проект для MSVC (Visual Studio с компонентом Desktop development with C++):

```powershell
cmake -S . -B build/msvc -A x64
cmake --build build/msvc --config Release
```

Результат: `build/msvc/Release/ThermalOverlay.exe`. Поставляемая сборка получена LLVM-MinGW; вариант MSVC в текущей среде не проверялся.

## Проверка

```powershell
$p = Start-Process ./build/ThermalOverlay.exe -ArgumentList '--smoke-test' -PassThru
$p.WaitForExit()
$p.ExitCode
```

Код 0 означает успешную проверку запуска, получения загрузки CPU, записи цвета/прозрачности/показателей/источника, сохранения положения, стилей поверх окон и прозрачности. Тест использует отдельный временный INI; реальные настройки не перезаписывает. Проверка доступности всех аппаратных температур требует соответствующего оборудования и провайдера.

## Git и приватность

Исходники не содержат учётных данных, личных путей и аппаратных идентификаторов конкретного компьютера. Программа не использует телеметрию, сетевую отправку и авторизацию. Настройки хранятся вне каталога проекта.

`.gitignore` исключает сборки, отладочные символы, локальные настройки IDE, конфигурацию окружения и типовые файлы ключей. Готовый EXE удобно прикладывать к GitHub Release; папка `build` остаётся локальной. Не добавляйте исключённые файлы через `git add -f` без проверки. Компилятор расположен вне проекта и в репозиторий не требуется.
