# ThermalOverlay

Небольшой виджет для Windows 11 x64 на C++17 и Win32. Окно всегда поверх обычных окон, поддерживает перетаскивание, прозрачность и изменение цвета. CPU и GPU отображаются одновременно в двух горизонтально расположенных карточках с обрамлением (CPU слева, GPU справа); в каждой по умолчанию есть загрузка и температура. Недоступные значения обозначаются `--`.

## Запуск и управление

Запустите `build/ThermalOverlay.exe`. Сам виджет не требует установки, .NET, Visual C++ Redistributable или прав администратора. Для встроенной температуры CPU требуется однократная установка подписанного PawnIO и нашей службы. Переносите всю папку `build`, чтобы установочные компоненты были доступны.

- Перетаскивание: за заголовок THERMAL, заголовки карточек или свободную область.
- Нажмите строку «Загрузка» или «Температура»: откроется список источников для этой строки. Выбор сразу применяется и сохраняется. У выбранного пункта стоит отметка.
- ПКМ или кнопка «Меню»: общие настройки, видимость показателей, прозрачность, цвет фона, автозагрузка, справка и выход.
- Кнопка «−» между меню и закрытием сворачивает окно в трей. Нажатие на значок возвращает окно; ПКМ по значку открывает «Показать» и «Выход». Повторный запуск EXE также возвращает скрытое окно.
- Кнопка закрытия справа оформлена отдельно и подсвечивается красным при наведении. Она полностью завершает программу. Окно имеет скруглённые углы.
- «Запускать при входе в Windows» добавляет или удаляет запись текущего пользователя в `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`. По умолчанию выключено. После переноса EXE в другой каталог выключите и снова включите этот пункт; системное отключение автозагрузки через Диспетчер задач может дополнительно блокировать запуск.
- Карточки CPU и GPU остаются видимыми: последний показатель в каждой карточке отключить нельзя.
- Прозрачность от 0 до 80%; цвет можно выбрать из готовых или задать самостоятельно. Прозрачность применяется ко всему окну, включая текст и рамки. На светлом фоне обрамление и текст тёмные для читаемости.
- Положение окна, цвет, прозрачность, видимость строк и выбранные источники сохраняются сразу в `%LOCALAPPDATA%\ThermalOverlay\settings.ini`.
- После отключения монитора окно перемещается в доступную рабочую область. Поддерживается масштабирование DPI на разных мониторах.

## Графики

Под показателями каждой карточки отображается общий график за последние 3 минуты: голубая линия — загрузка (0–100 %), оранжевая — температура (0–150 °C). Подписи показателей и шкал окрашены в соответствующие цвета. Шкалы независимые: высота линий не означает равенство процентов и градусов. История заполняется с момента запуска, хранится только в памяти и продолжает собираться при сворачивании в трей. Недоступные значения и длительные задержки дают разрыв линии. При смене источника очищается история только этого показателя. Видимость графика следует за видимостью соответствующей строки.

## Источники данных и ограничения

CPU, загрузка: `GetSystemTimes`, средняя загрузка всех логических процессоров основной процессорной группы. На машинах с более чем 64 логическими процессорами это ограничение Windows API нужно учитывать.

GPU, загрузка: Windows PDH `GPU Engine`. Значения процессов суммируются отдельно для каждого аппаратного движка, затем выбирается самый загруженный движок среди GPU. Это не сумма процентов всех движков. Тот же принцип используется Диспетчером задач. В меню доступны отдельные движки Windows (3D, Copy и другие, которые предоставляет драйвер). Замеры выполняются с интервалом около секунды; несовпадающие моменты обновления могут давать разные цифры при меняющейся нагрузке.

GPU, температура: `D3DKMTQueryAdapterInfo`, `KMTQAITYPE_ADAPTERPERFDATA`, максимум доступных температур аппаратных адаптеров. Значение зависит от поддержки драйвером; показания округляются до целых градусов, как в Диспетчере задач. Загрузка и максимальная температура при нескольких GPU могут относиться к разным адаптерам.

На NVIDIA дополнительно доступны температура и загрузка каждой GPU через штатную `nvml.dll` из драйвера. Они выбираются вручную в меню строки. NVML использует другую методику загрузки, поэтому его процент не обязан совпадать с Диспетчером задач. Отсутствие NVML не мешает работе.

CPU, резервный источник: максимум доступных температур CPU из локального WMI-провайдера запущенного [Libre Hardware Monitor](https://github.com/LibreHardwareMonitor/LibreHardwareMonitor/releases). Он также добавляет в выпадающие меню отдельные датчики CPU/GPU: ядра, пакет CPU, отдельные нагрузки и температуры. Для доступа к аппаратным датчикам самому Libre Hardware Monitor могут потребоваться права администратора. Он не включён в поставку и не запускается виджетом автоматически. Идентификатор рядом с названием помогает различать одноимённые датчики разных устройств.

**У Windows нет универсального пользовательского API температуры CPU.** Программа получает её через встроенную службу PawnIO или резервный WMI-провайдер. Без обоих источников будет `--`. Температура ACPI-зоны не выдаётся за температуру CPU. Если выбранный датчик отключился или исчез, виджет сохраняет выбор и показывает `--` до его возвращения. Первая загрузка может появиться через несколько секунд. Номинальный интервал опроса — одна секунда (при долгом ответе провайдера он может увеличиться); работа провайдера не блокирует интерфейс.

Поверх полноэкранных игр в эксклюзивном режиме и защищённого рабочего стола Windows отображение не гарантируется. Для игр подходит оконный режим без рамки. Сборка x64 рассчитана на Windows 11 x64; работа на Windows on ARM через эмуляцию отдельно не проверялась. Поддержку датчиков на каждом компьютере гарантировать нельзя.

## Температура Intel и AMD: первый запуск

При запуске проверяются CPUID, наличие PawnIO и службы ThermalOverlayCpu. Если один из компонентов отсутствует, появляется объяснение и предложение установить только недостающие части. Можно отказаться: виджет продолжит работать, повторная настройка доступна через «Настроить температуру CPU…». Если драйвер и служба уже установлены, повторного предложения нет. Уже установленный драйвер не заменяется. Системно отключённая или остановленная установленная служба не переустанавливается: её состояние можно проверить в оснастке служб Windows.

После согласия Windows запросит UAC для setup-cpu.ps1. Скрипт проверяет подпись и SHA-256 официального установщика, устанавливает обычную подписанную редакцию PawnIO, копирует службу и модули в защищённый `%ProgramFiles%\ThermalOverlay`, создаёт автоматически запускаемую службу. Политика выполнения PowerShell задаётся только для процесса установки; системные политики, Secure Boot и защита памяти Windows не меняются. При необходимости перезагрузки установщик сообщает об этом.

Само окно работает без повышения прав. Служба запускается от LocalSystem, читает только температурные регистры и публикует ограниченный снимок температур в локальной общей памяти с доступом пользователей только на чтение. Нет команд управления аппаратурой, сетевого интерфейса или записи частот, напряжений и лимитов мощности. Служба продолжает работать после закрытия виджета.

- Intel с DTS: TjMax читается из IA32_TEMPERATURE_TARGET; проверяется бит достоверности IA32_THERM_STATUS/IA32_PACKAGE_THERM_STATUS. По умолчанию CPU Package; отдельные физические ядра доступны в списке. Недостоверные значения и неизвестный TjMax не подменяются предположениями.
- AMD Ryzen семейства 17h, 19h и 1Ah: Tdie из SMN THM_TCON_CUR_TMP, с учётом диапазона и известных смещений Tctl. При наличии смещения Tctl также доступен отдельно. Устаревшие AMD и многосокетные AMD-системы этим прямым источником не поддерживаются.
- Libre Hardware Monitor остаётся резервным источником и может добавить другие датчики.

Служба и формулы скомпилированы и проверены программными тестами. Установка и реальные аппаратные показания Intel/AMD пока не проверены: по решению пользователя первый запуск с установкой будет выполнен вручную. Наличие аппаратных блокировок или неподдерживаемого CPU может оставить значение `--`.

Для удаления нашей службы выполните в PowerShell администратора:

```powershell
Stop-Service ThermalOverlayCpu
sc.exe delete ThermalOverlayCpu
```

Это не удаляет общий драйвер PawnIO: им могут пользоваться другие приложения. При необходимости он удаляется отдельно через установленные приложения Windows.

## Сборка

Переносимый LLVM-MinGW (UCRT, x86_64), PowerShell:

```powershell
.\build.ps1 -Compiler 'X:\tools\llvm-mingw\bin\clang++.exe'
```

Путь в примере условный. Если `clang++` есть в PATH, достаточно `./build.ps1`. Получится `build/ThermalOverlay.exe`. Скрипт не содержит путей конкретного пользователя. При отсутствии локального установщика он загружает официальный PawnIO 2.2.0 и проверяет закреплённый SHA-256. Модули Intel/AMD и их лицензия находятся в third_party/pawnio.

Также есть CMake-проект для MSVC (Visual Studio с компонентом Desktop development with C++):

```powershell
cmake -S . -B build/msvc -A x64
cmake --build build/msvc --config Release
```

Результат: `build/msvc/Release/ThermalOverlay.exe` и служба рядом с ним. Для установки CPU скопируйте проверенный `cpu-support/PawnIO_setup.exe` из полного пакета build.ps1 в каталог этой сборки. Поставляемая сборка получена LLVM-MinGW; вариант MSVC в текущей среде не проверялся.

## Проверка

```powershell
$p = Start-Process ./build/ThermalOverlay.exe -ArgumentList '--smoke-test' -PassThru
$p.WaitForExit()
$p.ExitCode
```

Код 0 означает успешную проверку запуска, получения загрузки CPU, записи цвета/прозрачности/показателей/источника, сохранения положения, стилей поверх окон и прозрачности. Тест использует отдельный временный INI; реальные настройки не перезаписывает. Проверка доступности всех аппаратных температур требует соответствующего оборудования и провайдера.

## Git и приватность

Исходники не содержат учётных данных, личных путей и аппаратных идентификаторов конкретного компьютера. Программа не использует телеметрию, сетевую отправку и авторизацию. Настройки хранятся вне каталога проекта.

`.gitignore` исключает сборки, отладочные символы, локальные настройки IDE, конфигурацию окружения и типовые файлы ключей. Готовый EXE удобно прикладывать к GitHub Release; папка `build` остаётся локальной. Не добавляйте исключённые файлы через `git add -f` без проверки. Компилятор расположен вне проекта и в репозиторий не требуется.
